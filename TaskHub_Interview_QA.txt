Milestone 1 — Project & Backend Foundation

1. What is TaskHub's overall architecture?

Answer: React web and React Native mobile clients communicate with a Node.js/Express REST API. The backend uses
Prisma to access PostgreSQL, with AWS/Firebase and monitoring/testing/CI tools added around the core system.

2. What is Node.js?

Answer: Node.js is a JavaScript runtime based on Chrome's V8 engine that lets us execute JavaScript or TypeScript on
the server.

3. Why use Express.js?

Answer: Express is a lightweight Node.js framework for HTTP servers and REST APIs. It provides routing, middleware,
request/response handling, and error handling.

4. What is middleware?

Answer: Middleware is a function that runs during the Express request-response lifecycle. It can authenticate, validate, log,
parse data, or handle errors.

5. What is CORS?

Answer: CORS controls which browser origins can access an API. It matters when the frontend and backend run on
different origins.

6. Why use Helmet?

Answer: Helmet adds security-related HTTP headers to Express responses and helps establish safer browser defaults.

7. Why use dotenv?

Answer: dotenv loads configuration from environment variables, keeping values such as database URLs and secrets out of
application source code.

8. Why use Zod?

Answer: Zod validates incoming data at runtime and works well with TypeScript. We can validate request bodies,
parameters, queries, and configuration.

9. Why TypeScript?

Answer: TypeScript provides static typing, better IDE support, safer refactoring, and clearer contracts across the full-stack
codebase.

10. What is REST?

Answer: REST is an architectural style for resource-oriented HTTP APIs. GET reads, POST creates, PATCH updates
partially, and DELETE removes resources.

11. 401 vs 403?

Answer: 401 means authentication is missing or invalid. 403 means the request is understood but the authenticated user is
not allowed to perform the operation.

12. What is ESLint?

Answer: ESLint statically analyzes JavaScript or TypeScript and flags problematic patterns and consistency issues before
runtime.

13. Why GitHub Actions?

Answer: GitHub Actions automates CI/CD. TaskHub can run lint, tests, type checks, builds, and later deployment
workflows on pushes or pull requests.

14. Why a monorepo?

Answer: A monorepo keeps web, mobile, backend, and shared packages in one repository, making shared types and
coordinated changes easier to manage.

15. What is an HTTP status code 201?

Answer: 201 Created indicates that a request successfully created a new resource, commonly returned by a successful
POST create operation.

Milestone 2 — PostgreSQL + Prisma

1. What is PostgreSQL?

Answer: PostgreSQL is an open-source relational database. It stores structured data in tables and supports relationships,
constraints, indexes, and transactions.

2. Why PostgreSQL for TaskHub?

Answer: TaskHub has strongly related data such as users, projects, memberships, and tasks. A relational database
provides strong integrity and transaction support.

3. What is Prisma?

Answer: Prisma is a TypeScript-friendly ORM/database toolkit that provides a schema, migrations, generated client, and
type-safe queries.

4. What is an ORM?

Answer: Object-Relational Mapping lets application code work with database records through programming-language
objects and methods rather than writing SQL for every operation.

5. PostgreSQL vs Prisma?

Answer: PostgreSQL is the database that stores the data. Prisma is the application-side data-access layer used by our
TypeScript backend to communicate with it.

6. What is a primary key?

Answer: A primary key uniquely identifies a row. In TaskHub, entities use UUID string IDs.

7. What is a foreign key?

Answer: A foreign key references a key in another table and maintains a relationship, such as Project.ownerId referencing
User.id.

8. What is one-to-many?

Answer: One record can relate to many records. For example, one user can own multiple projects.

9. What is many-to-many?

Answer: Many users can belong to many projects. TaskHub represents this with the ProjectMember junction table.

10. Why ProjectMember?

Answer: It implements the many-to-many relationship and also stores membership-specific information such as OWNER,
MANAGER, or MEMBER.

11. What is a unique constraint?

Answer: A unique constraint prevents duplicate values. TaskHub makes user email unique to prevent duplicate
registrations.

12. What is an index?

Answer: An index speeds up searches and filtering on selected columns. It improves reads but uses storage and adds
some write overhead.

13. What is a migration?

Answer: A migration is a version-controlled database schema change that can be applied consistently across
development, staging, and production.

14. prisma migrate vs prisma generate?

Answer: migrate creates/applies schema migrations; generate creates the Prisma Client code used by the application.

15. When use raw SQL?

Answer: Prisma is preferred for normal application queries, but raw SQL can be justified for complex queries,
database-specific features, or cases requiring precise SQL control.

Milestone 3 — REST API + Backend Architecture

1. Why layered architecture?

Answer: Separating controllers, services, and repositories keeps responsibilities clear, improves testing, and makes the
backend easier to maintain.

2. What does a Controller do?

Answer: It handles HTTP concerns: reads validated input, calls the appropriate service, and builds the HTTP response.
Complex business logic should not live there.

3. What does a Service do?

Answer: A service contains business/application logic and coordinates repositories or other services without depending
heavily on Express request/response objects.

4. What does a Repository do?

Answer: A repository abstracts database access, keeping Prisma queries and persistence details separate from business
logic.

5. Why not put Prisma queries in controllers?

Answer: That makes controllers large and tightly coupled to the database. Repositories centralize data access and make
services easier to test.

6. Explain the request flow.

Answer: Client → Express route → middleware → controller → service → repository → Prisma → PostgreSQL, then the
result travels back to the client.

7. What is validation?

Answer: Validation verifies that incoming data follows the API contract before business logic executes. Zod is used for
runtime schema validation.

8. Authentication vs authorization?

Answer: Authentication answers who the user is. Authorization answers what that user is allowed to do.

9. What is JWT?

Answer: JSON Web Token is a signed token containing claims that a server can verify. TaskHub will use JWTs for API
authentication.

10. Why access and refresh tokens?

Answer: A short-lived access token limits exposure if stolen. A refresh token allows a client to obtain a new access token
without frequent login.

11. What is centralized error handling?

Answer: A common Express error middleware converts known application errors into consistent responses and logs
unexpected errors.

12. Why version APIs?

Answer: Versioning such as /api/v1 lets the backend evolve without immediately breaking existing web and mobile clients.

13. What is Swagger/OpenAPI?

Answer: OpenAPI is a standard API description format. Swagger tooling can render interactive documentation for
developers and testers.

14. What is Jest?
TaskHub Interview Guide • Page 7

Answer: Jest is a JavaScript/TypeScript testing framework used for unit tests and, with appropriate setup, integration tests.

15. What is Sentry?

Answer: Sentry monitors runtime errors and performance, providing stack traces and context that help diagnose
production problems.

Milestone 4  JWT and password hashing foundation

Q1. What is authentication?
A. Authentication is the process of verifying the identity of a user or system.

Q2. What is the difference between authentication and authorization?
A. Authentication answers "Who are you?", while authorization answers "What are you allowed to do?"

Q3. Why should passwords be hashed?
A. Passwords should be hashed instead of stored as plain text so the original password cannot simply be recovered if the database is compromised.

Q4. Why do we use bcrypt?
A. bcrypt is a password hashing algorithm designed to be computationally expensive, making brute-force password attacks more difficult.

Q5. What is JWT?
A. JWT stands for JSON Web Token. It is a signed token containing claims that the server can verify and use for authentication.

Q6. What are the three parts of a JWT?
A. A JWT contains a header, payload, and signature.

Q7. Is JWT encrypted?
A. No. A normal JWT is encoded and signed, not encrypted. Sensitive information should not be stored in the payload.

Q8. What is an access token?
A. An access token is a short-lived token used by the client to authenticate API requests.

Q9. What is a refresh token?
A. A refresh token is a longer-lived credential used to obtain a new access token without requiring the user to log in again.

Q10. Why should access tokens be short-lived?
A. Short-lived access tokens reduce the security impact if a token is stolen.

Q11. What is OAuth?
A. OAuth is a delegated authorization framework that allows an application to use an external provider such as Google for authentication or authorization without handling the provider's password.

Q12. Is OAuth the same as JWT?
A. No. OAuth is an authorization/authentication flow or framework, while JWT is a token format. OAuth can be used to authenticate a user and our application can then issue its own JWT.

Q13. Why do we use Zod in authentication?
A. Zod validates incoming request data at runtime and ensures that values such as email and password follow the expected API contract.

Q14. Why should validation happen on the backend?
A. Client-side validation improves user experience, but the backend must validate independently because clients cannot be trusted.

Q15. Why separate Controller, Service, and Repository?
A. The Controller handles HTTP requests, the Service contains business logic, and the Repository handles database access. This separation improves maintainability, testing, and scalability.

Q16. Why shouldn't database queries be directly inside controllers?
A. Direct database queries make controllers tightly coupled to the database and difficult to test. A repository keeps data-access logic separate.

Q17. What happens when a user logs in?
A. The backend finds the user, compares the submitted password with the stored bcrypt hash, generates authentication tokens, and returns the authenticated user information and tokens.

Q18. What happens when accessing a protected API?
A. The client sends the access token, authentication middleware verifies the JWT, extracts the user ID, and allows the request to continue if the token is valid.

Q19. What is authentication middleware?
A. Authentication middleware verifies the user's credentials or JWT before allowing access to protected routes.

Q20. Why should JWT secrets not be hardcoded?
A. JWT secrets are sensitive credentials. They should be stored in environment variables or a secure secrets manager so they are not exposed in source control and can be rotated safely.
